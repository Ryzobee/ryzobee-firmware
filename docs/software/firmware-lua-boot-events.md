# Lua BOOT 按键事件

本页描述 `feat/boot_event` 分支新增的通用接口，不代表已发布版本。
工程版本仍为 V0.10.2；仅凭版本文字不能判断固件是否包含此接口。

`require('boot').poll()` 让 App 和 legacy Lua 消费实体 BOOT 的单击、双击和
长按事件。`ryz-neuro` 不提供该模块。C 继续拥有 GPIO、采样、消抖与系统退出；
Lua 不读取原始引脚，不注册中断，不重配 GPIO，也不能禁用系统长按退出。

## 接口与返回值

```lua
local boot = require('boot')
local event, reason = boot.poll()
if event then
  print(event.type, event.held_ms, event.timestamp_ms)
elseif reason then
  print('BOOT ERROR', reason)
end
```

`poll()` 不接受参数，包括显式 `nil`；额外参数产生 Lua 参数错误。
每次调用最多消费一个事件，不等待新按键，也不替代主循环的短暂休眠。

| 返回 | 含义 |
| --- | --- |
| `event` | 成功消费一个事件，字段如下 |
| `nil`（仅一个返回值） | 队列正常且当前没有事件，不是错误 |
| `nil, 'unavailable'` | 当前平台/作业未提供 BOOT 事件后端 |
| `nil, 'busy'` | 后端当前忙，可在下一轮有界重试 |
| `nil, 'overflow'` | 有事件丢失；旧队列已清空，本次报告溢出；多故障同时出现时采样失败优先报告 `failed` |
| `nil, 'failed'` | 采样或后端故障，不能当作正常空队列 |

事件为普通 Lua table：

| 字段 | 类型与语义 |
| --- | --- |
| `type` | 字符串：`click`、`double_click` 或 `long_press` |
| `held_ms` | 整数，0..3000；单击为该次稳定按下的时长，双击为第二次按下的时长，长按为 3000 |
| `timestamp_ms` | C 确认事件并入队时的 uint32 单调毫秒采样时间戳，以**精确十进制字符串**返回，如 `"4294967295"`；不是 UTC，约 49.7 天回绕 |

当前冻结 Lua 使用 32 位整数/浮点。不要把 `timestamp_ms` 转成普通 number 后
仍宣称大数精确，也不要按字符串字典序比较先后。事件队列顺序由 C 提供；通常只需
按序消费，将时间戳作为记录字段。它不是跨重启的唯一事件 ID。
`click` 的时间戳为 350 ms 等待结束并确认事件的时刻，不是首次释放时刻；
`double_click` 为第二次释放确认时刻，`long_press` 为长按阈值被确认的采样时刻。

## 手势判定

C 按 20 ms 周期采样，稳定 40 ms 后确认电平变化。以下时间基于消抖后的状态；
实际观察还受采样、任务调度、Lua 轮询间隔和同步 native 调用影响，不是硬实时保证。

- **开始接收：**首次使用、新作业以及需要恢复的采样错误/溢出后，先稳定释放
  40 ms，再接收新的按下。启动脚本时已经按住的 BOOT 不会被当作一次新点击。
- **单击：**短按并释放后等待 350 ms，排除双击后才产生一个 `click`。
  因此短按不会在释放瞬间立即交付。
- **双击：**第二次稳定按下发生在首次稳定释放后的 350 ms 窗口内，且第二次
  按下在 3 秒之前释放，产生一个 `double_click`，不会再附送两个 `click`。
  第二次稳定按下恰好位于 350 ms 边界时，优先按双击处理。
- **长按：**稳定按下达到 3 秒时产生一次 `long_press`，持续按住不重复发出；
  随后释放也不会补发 `click`。双击窗口内的第二次按下若持续到 3 秒，按长按处理。
- **系统退出：**继续持有 BOOT 到约 5 秒，C 请求终止当前 Lua 作业并清理资源，
  返回系统界面。该行为不依赖 Lua 是否轮询，不能由脚本取消或更改阈值。

按下时长从稳定按下计到稳定释放。释放候选仍在消抖时暂缓确认，不能把原始电平
在 3 秒前变化理解为一定短按：例如 2990 ms 开始释放、3030 ms 才确认稳定释放，
会归为长按而不是单击。

**3 秒长按与 5 秒系统退出不是互斥事件。** 用户为退出而长按 5 秒时，Lua 可能
已经在 3 秒收到 `long_press`。不要把长按事件直接绑定删除存档、支付、发奖或
驱动危险输出等不可逆动作；需要额外确认或选择不会造成损害的操作。
系统取消不是回滚，也不能即时打断正在执行的同步 native 操作。

## 队列、协程与故障恢复

固件复用一个固定容量 **8 个事件**的静态队列，以当前作业身份隔离，不为每个
作业动态分配队列。主线程与协程消费同一队列，
**不是广播**：一个协程读走后，其它协程不会再得到副本。建议由一处轮询，
在 Lua 内按业务需要分发；不要让多个消费者互相抢事件。

作业结束/取消时清理其事件，不能把上一脚本的点击带入下一脚本。
新事件入队时若超过容量，则丢弃旧事件并暂停接收新手势。正常恢复流程先由
`poll()` 报告一次 `overflow`，再重新等待 40 ms 稳定释放后接收新的按下；
报告前的释放不会提前解锁。若同时遇到采样失败，优先报告 `failed`，不保证
多故障时每一种错误都单独通知。
脚本应撤销尚未完成的交互，不要根据残缺事件补算点击次数。
采样失败也不能伪造一次释放/点击；错误恢复后须重新按键。

每轮做有界工作，再 `board.sleep_ms(20)`。如需排空积压队列，限制每轮最多
读取 8 次；不要无间隔忙等，也不要让事件处理无限追加日志或历史记录。
共同的 BOOT 取消、期限和 Lua 堆限制仍然生效，没有 Lua ISR 或自动调度回调。

## 示例、适配与验证边界

源码示例：[boot_events_demo.lua](../../firmware/rootmaker/scripts/boot_events_demo.lua)。
它打印事件，最多轮询 3000 次、输出 24 条事件/溢出通知，每轮休眠 20 ms；
不创建 UI、不改 GPIO、不写文件、不设置自启。后台忙时稍后再试，后端不可用或失败
时报告并结束，溢出时提醒释放按键再操作。

该示例仅位于 `scripts/`，不会自动打包进出厂 `fs/`，也不修改 `boot.lua`。
同一原生模块支持 legacy 入口；示例本身使用 `ryz-app/1` marker。

普通 Host/模拟器没有注入 BOOT 后端时返回 `unavailable`，不能通过模拟器虚构
实体按键成功。Host 注入时序可检查消抖、双击窗口、队列与 Lua 返回契约；
不能替代实机的电气抖动、采样调度、触摸并行与 5 秒退出验收。
本页是接口说明，不宣称已经完成这些实机验证。

在仓库准备好锁定的 Lua 组件后，从 `firmware/rootmaker` 运行 Host 检查：

```sh
python3 -m unittest tests/test_boot_events.py tests/test_runtime_owner.py
```

前者检查 C 按键状态机与队列时序，后者通过冻结 Lua 的 App/legacy 公共入口
检查返回值、错误、协程与取消，并执行上述实际示例。检查是否通过以本次命令结果
为准；不要把测试名称或旧外设测试记录当作本次通过的证据。
