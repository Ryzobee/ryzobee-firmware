# RyzoBee Cyberdeck Interface 风格规范

本文定义 Ryzobee 软件界面的赛博终端视觉语言，供产品设计、Figma、前端实现及 AI 生成界面时使用。

品牌颜色与字体的最终依据是 docs 目录的 [`RyzoBee 配色与字体规范.md`](../RyzoBee%20配色与字体规范.md)。前端实现使用 [`assets/typography/src/theme.css`](../../assets/typography/src/theme.css) 中的现有变量。本文负责规定视觉风格和使用方式，不建立另一套品牌色或字体。

## 1. 风格名称与定位

内部统一名称：**RyzoBee Cyberdeck Interface**，中文可称为 **Ryzobee 赛博终端界面**。

对外描述：**品牌化的功能型赛博朋克 HUD**（branded functional cyberpunk HUD）。`Cyberpunk UI`、`Cyberdeck UI`、`Sci-Fi HUD` 和 `FUI` 可作为检索标签；产品界面优先使用 Cyberdeck Interface，而不是强调虚构感的 FUI。

一句话定义：

> 以黑色和深灰构建空间、白灰承载真实信息、Ryzobee 橙建立操作焦点，用高密度模块、切角边框和工程仪表语言呈现硬件与软件状态。

目标气质：**工程、精确、快速、可操作、克制**。界面可以有未来感，但每一个高亮、状态和数据区都应具有明确用途。

## 2. 设计原则

1. **功能优先**：先建立任务、数据和操作层级，再添加 HUD 装饰。
2. **高密度但可扫描**：通过分区、标签和对齐承载更多信息，不通过缩小正文或堆叠噪声制造复杂感。
3. **橙色克制**：橙色只承担品牌、关键操作、选择和焦点；使用越少，识别越强。
4. **状态语义稳定**：成功、信息、警告、错误各用自己的功能色，并同时提供文字或图标。
5. **真实系统感**：展示真实设备、运行、连接和任务状态。示例数据必须标记为 `DEMO` 或 `SAMPLE`。
6. **装饰可降级**：扫描线、坐标、编号和辉光可以移除，而不影响信息理解和操作。

## 3. 颜色系统

### 核心比例

深色界面采用约 **70 : 25 : 5** 的比例：

- 黑色与深灰：65–75%，构成背景和容器。
- 白色与灰色：20–30%，承载文字、图标和技术图形。
- Ryzobee Orange：5–10%，标记品牌和关键交互。

### 颜色与职责

| Token | 色值 | 职责 |
| --- | --- | --- |
| `--ryzo-black` | `#000000` | 最深背景、设备外框、沉浸区域 |
| `--ryzo-bg` | `#121212` | 页面背景 |
| `--ryzo-surface` | `#181818` | 一级面板、卡片、输入区域 |
| `--ryzo-surface-secondary` | `#242424` | 次级面板、嵌套数据区 |
| `--ryzo-border` | `#3A3A3A` | 默认边框、分隔线、网格 |
| `--ryzo-text-disabled` | `#666666` | 禁用内容 |
| `--ryzo-gray-500` | `#888888` | 弱化辅助信息 |
| `--ryzo-text-secondary` | `#A0A0A0` | 参数标签、元数据、说明 |
| `--ryzo-graphic` | `#BFBFBF` | 次级图形和技术插图 |
| `--ryzo-text-body` | `#D9D9D9` | 正文和长文本 |
| `--ryzo-text-primary` | `#FFFFFF` | 标题、关键数据、主要信息 |
| `--ryzo-orange` | `#FF6A00` | Logo、主要操作、选中、焦点、关键数据 |
| `--ryzo-success` | `#34C759` | 已连接、通过、完成、在线 |
| `--ryzo-info` | `#3B82F6` | 信息、链接、系统提示 |
| `--ryzo-warning` | `#FFB020` | 风险、注意、暂时异常、结果未知 |
| `--ryzo-error` | `#FF453A` | 失败、离线、超时、危险操作 |

### 参考风格的品牌化映射

- 将常见红色 Cyberpunk HUD 的主轮廓、高亮和按钮改为 `#FF6A00`。
- 将装饰性青色改为白灰层级；只有信息语义才使用 `#3B82F6`。
- `#FF453A` 只表示错误或危险，不能作为页面主色。
- `#FFB020` 只表示警告，不能替代品牌橙。
- 橙色实心按钮使用黑色文字。正文不使用大面积橙色。
- 发光效果从对应语义颜色派生，保持低透明度；默认边框仍使用 `#3A3A3A`。

## 4. 字体系统

### 字体职责

| 内容 | 字体 | 推荐字重 | 使用规则 |
| --- | --- | --- | --- |
| 英文品牌标题、产品名、展示大数字 | Teko | 500–700 | 可全大写；用于建立品牌个性 |
| 英文 UI、正文和技术信息 | Noto Sans | 400–700 | 承担真实信息和操作内容 |
| 中文 UI、正文和标题 | Noto Sans SC | 400–700 | 中文保持自然比例和字距 |
| 代码、Console、日志原文 | `--font-mono` | 400–600 | 只用于需要字符对齐的技术内容 |

字体变量：

```css
font-family: var(--font-display); /* Teko 展示字体 */
font-family: var(--font-sans);    /* Noto Sans / Noto Sans SC 信息字体 */
font-family: var(--font-mono);    /* 代码与 Console */
```

### 基础字号与层级

下表是品牌字号的通用参考，不代表所有终端共用一套密度。**手机、桌面网页采用后文的独立网页尺度；240×240 设备 UI 仍按各自经过真屏检查的页面规格执行。**

| 层级 | 建议规格 |
| --- | --- |
| 设备名、欢迎页标题 | Teko 600–700；32–56 px；行高 90–100% |
| 仪表大数字 | Teko 500–700；根据容器确定字号 |
| 页面 H1 | 英文 Teko/Noto Sans 600，中文 Noto Sans SC 700；40 px |
| H2 | Noto Sans / Noto Sans SC 600；32 px |
| H3 | Noto Sans / Noto Sans SC 600；24 px |
| 卡片标题 | Noto Sans / Noto Sans SC 600；18–20 px |
| 导航、按钮 | Noto Sans / Noto Sans SC 500；14–16 px |
| 输入、正文 | Noto Sans / Noto Sans SC 400；14–16 px |
| Caption | Noto Sans / Noto Sans SC 400；12 px |
| 技术标签 | Noto Sans / Noto Sans SC 500；11–12 px |

英文展示标题保持短、强、直接。Teko 全大写标题可使用 0–3% 字距；小型全大写 Noto Sans 标签可使用 5–10% 字距。中文正文保持正常字距，长文本行高使用 160–180%。

Teko 不承担中文、正文、参数、按钮、表单或小于 12 px 的信息。一个页面最多使用四个字重。

### 手机与桌面网页的独立尺度

配网页、诊断日志网页及后续浏览器页面共享 V5 的配色、字体职责和 HUD 语言，**不共享 240×240 设备屏的字号或固定画布约束**。高分辨率手机的物理像素不等于浏览器 CSS 像素；Figma 网页画板按目标 CSS 视口设计，不能按设备物理分辨率成比例缩小文字。

| 网页内容 | 字号 / 行高 | 使用规则 |
| --- | --- | --- |
| 正文、步骤说明、连接结果、重要提示 | 18 px / 26–28 px | 手机和桌面都以此为默认；长篇中文可增加至 160–180% 行高 |
| 日志、错误原文、调用栈 | 16 px / 24 px | 使用等宽字体；通过换行与滚动保留内容，不缩字换取更多行 |
| 按钮、输入、网络名称、关键参数 | 16–18 px / 24–28 px | 手机输入和可操作文字不小于 16 px；重要操作优先 18 px |
| 辅助标签、时间、来源、次要元数据 | 14 px / 20 px | 只承载辅助信息，不能把操作说明或错误原因降为小标签 |
| 卡片 / 分区标题 | 24–32 px | 沿用品牌字体职责；短展示标题可使用 Teko |
| 页面标题、品牌、主要错误码 | 32–56 px | 根据层级和容器选择，不以标题挤压正文空间 |

这是从现有品牌字号中选择的网页阅读尺度，不新增字体或颜色。不要在全局 `Firmware/...` 文字样式上直接放大字号来影响设备页面；网页应使用独立样式或明确的局部字号设置。

网页排版先为可读文字分配空间，再确定容器高度。手机允许纵向长页；桌面空间不足时也允许扩高或滚动。辅助内容先重排、收起或减少装饰，不为了“所有内容一屏放下”退回 12–14 px 正文。检查时按网页 100% 视图阅读，并检查长文件名、无空格错误串、多行提示和文本增长，而不只看缩小的整板预览。

## 5. 形状与空间语言

### 面板层级

1. **Chassis**：黑色或 `#121212` 的整体工作空间。
2. **Module Panel**：`#181818` 一级功能区，组织设备、项目或任务。
3. **Data Cell**：`#242424` 嵌套信息单元，承载参数、日志和状态。

面板使用 1 px `#3A3A3A` 轮廓。选中或键盘焦点使用清晰的品牌橙轮廓；重要操作可以使用橙色实心填充。圆角应小而克制，可使用切角或缺口建立机械结构感。不同层级依靠背景、间距和标题组织，不依赖持续发光。

推荐使用 4/8 px 基础间距体系，常用间距为 8、12、16、24 和 32 px。模块内元素按共同基线和网格对齐。

### 图形与装饰

- 图标采用简洁线性或实心几何风格，线宽和端点保持一致。
- 数据图以白灰为基础，橙色标记当前值、选中范围或关键节点。
- 技术编号、坐标、刻度、端口标识和短分隔线可增强终端感。
- 扫描线、网格、噪点和辉光属于低对比背景层，不能穿过正文或降低对比度。
- 阴影用于分离层级，不制造玻璃拟态。模糊透明面板不是本风格的主要特征。

## 6. 组件表现

| 组件 | 表现规则 |
| --- | --- |
| 原生系统顶部状态栏 | 紧凑展示设备、连接、时间和任务状态；状态必须包含文字或图标 |
| Lua 运行页 | 默认使用完整 240×240 画布，不放系统状态栏、系统返回或触摸退出按钮；顶部优先承载脚本内容与任务参数 |
| 导航 | 默认使用白灰；当前项使用橙色边框、指示条或局部填充 |
| 主要按钮 | 橙底黑字；动词短而直接 |
| 次要按钮 | 深色背景、灰色边框、白色文字；悬停时提高边框和文字亮度 |
| 模块卡片 | 深色分层、切角轮廓、明确标题；信息密度高但分组清楚 |
| 指标卡 | 大数字可用 Teko；单位、来源和状态用 Noto Sans |
| 图表 | 灰色建立上下文，橙色突出当前数据；功能色只表达状态 |
| Console / 日志 | 等宽字体；时间、来源、严重程度和正文列对齐 |
| 二维码 | 透明背景、纯白码点（`#FFFFFF`）；由页面纯黑/均匀深色背景承载，四周保留至少 4 模块无装饰静区；不能叠在文字、图片、纹理或渐变上 |
| 警告与错误 | 使用对应功能色、图标和明确动作，不用品牌橙伪装状态 |

二维码的透明底不表示可以省略静区：静区和码点间隙都必须透出均匀深色。保持原编码矩阵、整数模块和尺寸；白码深底方案需要目标手机与真屏扫码验收，设计截图不能替代扫码兼容性测试。Figma 的 `color/qr/module` 统一为白色，`color/qr/quiet-zone` 为透明。

## 7. 交互与动效

- **Lua 运行与系统导航分开**：运行中的脚本通过长按实体 BOOT 请求退出，清理资源后交还系统 UI；不通过页面返回按钮退出。脚本内部的 CANCEL / CONFIRM 只取消或确认局部操作，不结束脚本。启动脚本前的系统入口、原生设置/OTA、脚本退出后接管的系统报错页不属于 Lua 运行态，保留各自原生导航策略。
- Lua 日志工具优先把空间留给可读日志；EVA 风格斜切条纹、短刻度和边界标记仅作低占用装饰，不压在正文上，不用装饰警报伪装真实故障。
- 默认、悬停、按下、选中、焦点、禁用和进行中状态必须可区分。
- 键盘焦点使用可见的橙色外框，不能只靠背景色变化。
- 状态变化同时更新颜色、图标或文字，不能只依赖颜色。
- 常规反馈使用约 120–200 ms 的快速过渡。
- 发光脉冲只用于短暂确认或确有活动的状态，不让整个页面持续闪烁。
- 系统请求减少动态效果时，关闭扫描、脉冲和装饰动画。

## 8. 响应式与信息降级

屏幕变窄时按以下顺序降级：

1. 移除装饰性坐标、扫描线和非必要刻度。
2. 将并列模块改为堆叠或分页。
3. 收起次级元数据，但保留展开入口。
4. 保留主要状态、当前任务和关键操作。

网页正文默认 18 px，日志不小于 16 px，辅助文字不小于 14 px；不得通过缩字维持“一屏完整仪表盘”。手机保留一条清晰主路径，使用纵向滚动、堆叠或展开查看更多内容。240×240 设备页面沿用独立设备规格，不能将这里的网页尺寸直接套入固件。

## 9. AI 执行规则

AI 设计或实现 Ryzobee 界面时按以下顺序工作：

1. 读取品牌规范、本文件和现有 `theme.css`，确认任务所需组件与状态。
2. 先给出信息层级和用户主路径，再应用 Cyberdeck 视觉语言。
3. 为每个颜色标明语义；实现代码时复用现有 CSS 变量。
4. 先区分网页 CSS 视口与 240×240 设备画布；网页使用独立的大字号尺度。使用 Noto Sans / Noto Sans SC 完成可读信息，只在规定位置使用 Teko。
5. 为交互补齐默认、悬停、按下、焦点、禁用、加载、成功和失败状态。
6. 检查窄屏、文字增长、中文混排、键盘焦点、对比度和减少动效模式。

完成标准：所有颜色均能追溯到现有 token；所有文字均符合字体职责；错误、警告、信息、成功与品牌强调没有混用；移除装饰后功能仍完整；没有未标记的伪造系统数据。

## 11. 审核清单

- [ ] 页面主色是 Black × White × Orange，而不是红青双霓虹。
- [ ] 橙色占比克制，并只用于品牌、操作、选中与焦点。
- [ ] 四种功能色只承担固定状态语义。
- [ ] 中文与 UI 信息使用 Noto Sans SC / Noto Sans。
- [ ] Teko 只出现在展示标题、产品名或大数字中。
- [ ] 网页正文、日志、控件和辅助标签使用独立网页尺度，没有照搬 240×240 字号。
- [ ] 手机与桌面网页均按 100% 视图检查文字阅读、换行、容器高度与滚动内容。
- [ ] 面板、边框、文字层级和间距足以支持快速扫描。
- [ ] 装饰效果不影响文字对比度、焦点和操作反馈。
- [ ] 小屏通过重排和收起降级，而不是无限缩小内容。
- [ ] 代码实现复用 `theme.css`，没有新增近似灰色或第二套 token。
- [ ] 数据是真实值，或已明确标记为演示内容。
